# Capítulo III: Requirements Specification

## 3.1. User Stories

### Epics

| Epic ID | Epic | Alcance |
| --- | --- | --- |
| EP01 | Descubrimiento de servicios y acceso de usuarios | Landing Page, información del servicio, registro, inicio de sesión y acceso de cuidadoras/familiares. |
| EP02 | Gestión de adultos mayores | Registro y administración de adultos mayores y sus datos básicos de cuidado. |
| EP03 | Registros de salud y seguimiento diario | Citas médicas, exámenes, evidencias, resultados, signos vitales, estado de ánimo y reportes diarios. |
| EP04 | Seguimiento Familiar y Emergencias | Acceso de familiares, visualización del seguimiento, recordatorios, notificaciones e información para emergencias. |
| EP05 | Gestión de suscripciones y pagos | Planes, prueba gratuita, suscripción y distintos métodos de pago. |

### User Stories

| User Story ID | Título | Descripción | Criterios de Aceptación | Epic ID |
| --- | --- | --- | --- | --- |
| US01 | Conocer la propuesta de valor de Vitalita | Como visitante, deseo conocer el propósito y los beneficios de Vitalita para determinar si la solución responde a mis necesidades de seguimiento del cuidado de un adulto mayor. | **Escenario 1: Consulta general del servicio**<br>**Given** un visitante accede al sitio público de Vitalita<br>**When** consulta la información general del servicio<br>**Then** la información presenta el problema que aborda Vitalita, los segmentos a los que se dirige y los beneficios principales de la solución.<br><br>**Escenario 2: Identificación con un segmento objetivo**<br>**Given** un visitante pertenece al segmento de cuidadoras, enfermeras o familiares de un adulto mayor<br>**When** revisa la propuesta de valor del servicio<br>**Then** puede identificar cómo Vitalita contribuye a organizar el seguimiento y a centralizar la información del adulto mayor. | EP01 |
| US02 | Consultar las funcionalidades principales | Como visitante, deseo conocer las funcionalidades principales de Vitalita para comprender qué actividades de cuidado y seguimiento puede apoyar la plataforma. | **Escenario 1: Revisión de capacidades del producto**<br>**Given** un visitante consulta la información funcional de Vitalita<br>**When** revisa las capacidades disponibles<br>**Then** se describen el registro de adultos mayores, citas, exámenes, seguimiento diario, recordatorios, acceso familiar e informe de emergencia.<br><br>**Escenario 2: Diferenciación de responsabilidades**<br>**Given** un visitante revisa las funcionalidades del servicio<br>**When** compara las acciones disponibles para cuidadoras y familiares<br>**Then** la información distingue que la cuidadora registra el seguimiento y que el familiar accede principalmente en modalidad de consulta. | EP01 |
| US03 | Consultar los planes del servicio | Como visitante, deseo conocer los planes de Vitalita para evaluar las condiciones de acceso antes de registrarme o contratar una suscripción. | **Escenario 1: Consulta de alternativas de suscripción**<br>**Given** un visitante evalúa contratar Vitalita<br>**When** consulta los planes disponibles<br>**Then** puede conocer las modalidades vigentes, sus condiciones de uso y las capacidades asociadas a cada plan.<br><br>**Escenario 2: Identificación de modalidad freemium**<br>**Given** un visitante busca probar Vitalita sin contratar inicialmente un plan de pago<br>**When** consulta las condiciones del servicio<br>**Then** puede identificar la existencia de una modalidad freemium y sus limitaciones frente a los planes de pago. | EP01 |
| US04 | Acceder a la experiencia web de Vitalita | Como visitante, deseo acceder desde la información pública del servicio a la experiencia web de Vitalita para registrarme o utilizar una cuenta existente. | **Escenario 1: Acceso para nuevo usuario**<br>**Given** un visitante decide empezar a utilizar Vitalita y no posee una cuenta<br>**When** solicita acceder al servicio<br>**Then** el sistema permite continuar con el proceso de registro correspondiente.<br><br>**Escenario 2: Acceso para usuario registrado**<br>**Given** un visitante ya dispone de una cuenta de Vitalita<br>**When** solicita acceder al servicio<br>**Then** el sistema permite continuar con el proceso de autenticación. | EP01 |
| US05 | Registrar una cuenta de cuidadora o enfermera | Como cuidadora o enfermera, deseo crear una cuenta en Vitalita para gestionar de forma centralizada la información de los adultos mayores que tengo a cargo. | **Escenario 1: Registro satisfactorio**<br>**Given** una cuidadora o enfermera proporciona los datos obligatorios válidos y no existe una cuenta asociada a su identidad de acceso<br>**When** solicita crear su cuenta<br>**Then** el sistema registra la cuenta y le asigna el rol operativo de cuidadora o enfermera.<br><br>**Escenario 2: Registro de cuenta existente**<br>**Given** una cuidadora o enfermera intenta registrarse con una identidad de acceso ya asociada a una cuenta<br>**When** solicita crear una nueva cuenta<br>**Then** el sistema no crea una cuenta duplicada e informa que ya existe un registro asociado. | EP01 |
| US06 | Iniciar sesión con permisos según el rol | Como usuario registrado, deseo iniciar sesión en Vitalita para acceder únicamente a las operaciones permitidas para mi rol. | **Escenario 1: Autenticación válida**<br>**Given** un usuario registrado proporciona credenciales válidas<br>**When** solicita iniciar sesión<br>**Then** el sistema autentica al usuario y aplica los permisos correspondientes a su rol.<br><br>**Escenario 2: Autenticación inválida**<br>**Given** un usuario proporciona credenciales que no corresponden a una cuenta válida<br>**When** solicita iniciar sesión<br>**Then** el sistema rechaza el acceso y no expone información de los adultos mayores registrados. | EP01 |
| US07 | Registrar un adulto mayor | Como cuidadora o enfermera, deseo registrar a un adulto mayor para iniciar su seguimiento dentro de Vitalita. | **Escenario 1: Registro válido de adulto mayor**<br>**Given** una cuidadora autenticada cuenta con autorización para gestionar un nuevo adulto mayor<br>**When** registra los datos básicos de cuidado requeridos<br>**Then** el sistema crea el perfil del adulto mayor y lo asocia a la cuidadora responsable.<br><br>**Escenario 2: Datos obligatorios incompletos**<br>**Given** una cuidadora intenta registrar un adulto mayor sin completar los datos obligatorios<br>**When** solicita guardar el registro<br>**Then** el sistema no crea el perfil hasta que la información requerida sea completada correctamente. | EP02 |
| US08 | Consultar el perfil de un adulto mayor | Como cuidadora o enfermera, deseo consultar el perfil de un adulto mayor a mi cargo para revisar sus datos básicos y antecedentes disponibles antes de realizar el seguimiento. | **Escenario 1: Consulta de paciente asociado**<br>**Given** una cuidadora tiene asociado un adulto mayor<br>**When** consulta su perfil<br>**Then** el sistema proporciona los datos básicos y la información de cuidado disponible correspondiente a ese adulto mayor.<br><br>**Escenario 2: Consulta de paciente no asociado**<br>**Given** una cuidadora intenta consultar un adulto mayor que no está asociado a su cuenta<br>**When** solicita acceder a su perfil<br>**Then** el sistema impide el acceso a la información del adulto mayor. | EP02 |
| US09 | Actualizar los datos básicos del adulto mayor | Como cuidadora o enfermera, deseo actualizar los datos básicos de un adulto mayor para mantener vigente la información utilizada durante su cuidado. | **Escenario 1: Actualización válida**<br>**Given** una cuidadora gestiona un adulto mayor registrado<br>**When** modifica datos básicos con valores válidos<br>**Then** el sistema conserva los cambios y mantiene el perfil asociado al mismo adulto mayor.<br><br>**Escenario 2: Actualización con datos inválidos**<br>**Given** una cuidadora intenta actualizar el perfil con información que no cumple las validaciones requeridas<br>**When** solicita registrar los cambios<br>**Then** el sistema no reemplaza la información válida existente por datos inválidos. | EP02 |
| US10 | Gestionar múltiples adultos mayores | Como cuidadora o enfermera, deseo gestionar más de un adulto mayor desde mi cuenta para organizar el trabajo cuando atiendo a varios pacientes. | **Escenario 1: Consulta de varios pacientes**<br>**Given** una cuidadora tiene más de un adulto mayor asociado y su plan permite gestionarlos<br>**When** consulta los adultos mayores a su cargo<br>**Then** el sistema permite identificar y acceder al seguimiento de cada adulto mayor de forma independiente.<br><br>**Escenario 2: Separación de información por paciente**<br>**Given** una cuidadora administra varios adultos mayores<br>**When** registra o consulta información de uno de ellos<br>**Then** el sistema mantiene los registros asociados únicamente al adulto mayor seleccionado. | EP02 |
| US11 | Invitar a un familiar autorizado | Como cuidadora o enfermera, deseo invitar a un familiar del adulto mayor para que pueda consultar su seguimiento sin depender de reportes manuales constantes. | **Escenario 1: Invitación de familiar**<br>**Given** una cuidadora gestiona un adulto mayor registrado<br>**When** asocia a un familiar autorizado con el adulto mayor<br>**Then** el sistema registra la relación y habilita al familiar para consultar el seguimiento correspondiente.<br><br>**Escenario 2: Permisos de solo lectura**<br>**Given** un familiar se encuentra asociado a un adulto mayor mediante una invitación válida<br>**When** accede a la información del seguimiento<br>**Then** el sistema permite la consulta y restringe la modificación de los registros creados por la cuidadora. | EP02 |
| US12 | Proveer servicios REST para gestionar adultos mayores | Como Developer, deseo disponer de servicios RESTful para registrar, consultar y actualizar adultos mayores para integrar estas operaciones con la aplicación web. | **Escenario 1: Request válido de gestión**<br>**Given** un cliente autorizado envía una solicitud válida para crear, consultar o actualizar un adulto mayor<br>**When** el servicio procesa la solicitud<br>**Then** la API devuelve una respuesta coherente con la operación realizada y el recurso afectado.<br><br>**Escenario 2: Request inválido o no autorizado**<br>**Given** un cliente envía una solicitud con datos inválidos o sin autorización suficiente<br>**When** el servicio procesa la solicitud<br>**Then** la API rechaza la operación y devuelve un resultado de error sin modificar información válida. | EP02 |
| US13 | Registrar un reporte diario | Como cuidadora o enfermera, deseo registrar el estado diario del adulto mayor para conservar un seguimiento ordenado de su evolución durante la jornada. | **Escenario 1: Registro del estado diario**<br>**Given** una cuidadora tiene asociado un adulto mayor<br>**When** registra observaciones, estado de ánimo y demás información diaria requerida<br>**Then** el sistema guarda el reporte con su fecha y lo vincula al historial del adulto mayor.<br><br>**Escenario 2: Consulta posterior del reporte**<br>**Given** existe un reporte diario registrado para un adulto mayor<br>**When** un usuario autorizado consulta su seguimiento<br>**Then** el sistema incluye el reporte dentro del historial correspondiente al paciente. | EP03 |
| US14 | Registrar signos vitales | Como cuidadora o enfermera, deseo registrar los signos vitales del adulto mayor para mantener un historial de sus controles durante el cuidado diario. | **Escenario 1: Registro de controles válidos**<br>**Given** una cuidadora realiza controles de signos vitales a un adulto mayor<br>**When** registra valores válidos como presión arterial, saturación, frecuencia cardíaca, temperatura o glucosa según corresponda<br>**Then** el sistema conserva los valores asociados al adulto mayor y al momento del registro.<br><br>**Escenario 2: Registro con formato inválido**<br>**Given** una cuidadora intenta registrar un signo vital con un valor que no cumple el formato esperado<br>**When** solicita guardar el control<br>**Then** el sistema no incorpora el dato inválido al historial y solicita su corrección. | EP03 |
| US15 | Registrar la administración de medicamentos | Como cuidadora o enfermera, deseo registrar la administración de medicamentos para mantener control del horario y reducir el riesgo de duplicidades u olvidos. | **Escenario 1: Administración registrada**<br>**Given** un adulto mayor tiene una medicación planificada<br>**When** la cuidadora registra que una dosis fue administrada<br>**Then** el sistema conserva la administración con referencia al medicamento, al paciente y al horario correspondiente.<br><br>**Escenario 2: Prevención de duplicidad**<br>**Given** ya existe un registro de administración para la misma medicación y horario<br>**When** se intenta registrar nuevamente la misma administración<br>**Then** el sistema evita que se confirme una duplicidad sin que la situación sea identificada. | EP03 |
| US16 | Registrar una cita médica | Como cuidadora o enfermera, deseo registrar las citas médicas del adulto mayor para mantener organizadas las atenciones y consultas programadas. | **Escenario 1: Registro de cita**<br>**Given** una cuidadora conoce los datos de una cita médica del adulto mayor<br>**When** registra la fecha, el tipo o especialidad y la información disponible de la cita<br>**Then** el sistema incorpora la cita al seguimiento del adulto mayor.<br><br>**Escenario 2: Consulta de cita registrada**<br>**Given** una cita médica se encuentra registrada para un adulto mayor<br>**When** un usuario autorizado consulta su seguimiento<br>**Then** el sistema proporciona la información vigente de la cita asociada al paciente. | EP03 |
| US17 | Registrar el resultado de una cita médica | Como cuidadora o enfermera, deseo registrar el resultado y las observaciones posteriores a una cita para conservar las indicaciones relevantes dentro del historial del adulto mayor. | **Escenario 1: Registro posterior a la consulta**<br>**Given** existe una cita médica registrada y la atención ya fue realizada<br>**When** la cuidadora registra el resultado y las observaciones disponibles<br>**Then** el sistema vincula la información a la cita y al historial médico del adulto mayor.<br><br>**Escenario 2: Consulta de resultado**<br>**Given** una cita contiene resultado y observaciones registradas<br>**When** un usuario autorizado consulta el historial del adulto mayor<br>**Then** el sistema presenta la información asociada a esa atención sin modificar el registro original. | EP03 |
| US18 | Registrar un examen médico | Como cuidadora o enfermera, deseo registrar los exámenes del adulto mayor para mantener organizadas sus solicitudes, resultados y antecedentes. | **Escenario 1: Registro de examen**<br>**Given** una cuidadora dispone de información sobre un examen indicado o realizado<br>**When** registra los datos disponibles del examen<br>**Then** el sistema incorpora el examen al historial del adulto mayor.<br><br>**Escenario 2: Seguimiento de resultado pendiente**<br>**Given** un examen se encuentra registrado sin resultado disponible<br>**When** la cuidadora consulta el seguimiento<br>**Then** el sistema mantiene el examen identificado como pendiente hasta que se registre su resultado. | EP03 |
| US19 | Adjuntar evidencia fotográfica de un examen | Como cuidadora o enfermera, deseo adjuntar evidencia fotográfica a un examen para conservar el respaldo del resultado junto con el registro correspondiente. | **Escenario 1: Adjunto de evidencia**<br>**Given** existe un examen registrado para un adulto mayor<br>**When** la cuidadora adjunta una evidencia fotográfica válida<br>**Then** el sistema vincula la evidencia al examen y la mantiene asociada al mismo paciente.<br><br>**Escenario 2: Registro sin evidencia inmediata**<br>**Given** la cuidadora registra un examen y todavía no dispone de evidencia fotográfica<br>**When** guarda la información del examen<br>**Then** el sistema permite conservar el examen y adjuntar la evidencia posteriormente. | EP03 |
| US20 | Registrar terapias y actividades de cuidado | Como cuidadora o enfermera, deseo registrar terapias y actividades de cuidado para mantener trazabilidad de las acciones realizadas durante la atención diaria. | **Escenario 1: Registro de actividad de cuidado**<br>**Given** un adulto mayor tiene una terapia o actividad de cuidado realizada<br>**When** la cuidadora registra la actividad y la fecha correspondiente<br>**Then** el sistema incorpora la actividad al seguimiento del adulto mayor.<br><br>**Escenario 2: Consulta de actividades previas**<br>**Given** existen terapias o actividades registradas para un adulto mayor<br>**When** un usuario autorizado consulta su historial<br>**Then** el sistema permite conocer las actividades registradas y su relación con el paciente. | EP03 |
| US21 | Proveer servicios REST para registros de salud | Como Developer, deseo disponer de servicios RESTful para gestionar reportes diarios, signos vitales, medicación, citas, exámenes y evidencias para integrar el núcleo de seguimiento con la aplicación web. | **Escenario 1: Request válido de registro o consulta**<br>**Given** un cliente autorizado envía una solicitud válida sobre un recurso de seguimiento de salud<br>**When** el servicio procesa la solicitud<br>**Then** la API devuelve una respuesta coherente con la operación y mantiene el recurso asociado al adulto mayor correspondiente.<br><br>**Escenario 2: Request con recurso o datos inválidos**<br>**Given** un cliente envía una solicitud con un recurso inexistente, datos inválidos o permisos insuficientes<br>**When** el servicio procesa la solicitud<br>**Then** la API devuelve un resultado de error y no altera los registros válidos del historial. | EP03 |
| US22 | Consultar el panel familiar de solo lectura | Como familiar autorizado, deseo consultar el seguimiento del adulto mayor para mantenerme informado sin depender de llamadas o mensajes constantes a la cuidadora. | **Escenario 1: Consulta de seguimiento autorizado**<br>**Given** un familiar está asociado a un adulto mayor<br>**When** consulta su seguimiento<br>**Then** el sistema proporciona la información disponible sobre reportes recientes, citas, exámenes y demás registros autorizados.<br><br>**Escenario 2: Restricción de modificación**<br>**Given** un familiar consulta la información de un adulto mayor asociado<br>**When** intenta modificar un registro creado por la cuidadora<br>**Then** el sistema impide la modificación porque el acceso del familiar es de solo lectura. | EP04 |
| US23 | Consultar el historial centralizado del adulto mayor | Como familiar autorizado, deseo consultar un historial centralizado para localizar rápidamente la información médica y de seguimiento que actualmente puede quedar dispersa entre mensajes, fotos o registros físicos. | **Escenario 1: Consulta de historial consolidado**<br>**Given** un familiar está autorizado a consultar a un adulto mayor<br>**When** solicita revisar su historial<br>**Then** el sistema reúne los registros de seguimiento disponibles correspondientes únicamente a ese adulto mayor.<br><br>**Escenario 2: Localización de información previa**<br>**Given** existen citas, exámenes, resultados o reportes previamente registrados<br>**When** el familiar consulta el historial del adulto mayor<br>**Then** el sistema permite recuperar esos antecedentes sin depender de mensajes enviados por la cuidadora. | EP04 |
| US24 | Recibir notificaciones ante actualizaciones relevantes | Como familiar autorizado, deseo recibir notificaciones sobre cambios relevantes en el seguimiento para conocer oportunamente situaciones que requieran mi atención. | **Escenario 1: Generación de notificación relevante**<br>**Given** una cuidadora registra una actualización clasificada como relevante para un adulto mayor<br>**When** el sistema procesa el nuevo registro<br>**Then** se genera una notificación para los familiares autorizados asociados al adulto mayor.<br><br>**Escenario 2: Protección de destinatarios**<br>**Given** una persona no está asociada al adulto mayor<br>**When** se genera una notificación sobre su seguimiento<br>**Then** el sistema no dirige la notificación a esa persona. | EP04 |
| US25 | Recibir recordatorios automáticos de actividades pendientes | Como cuidadora o enfermera, deseo recibir recordatorios sobre citas, terapias y actividades pendientes para reducir el riesgo de olvidos durante el cuidado del adulto mayor. | **Escenario 1: Recordatorio de actividad próxima**<br>**Given** existe una cita, terapia o actividad pendiente con fecha programada<br>**When** se aproxima el momento correspondiente según la regla de anticipación definida<br>**Then** el sistema genera un recordatorio asociado al adulto mayor y a la actividad pendiente.<br><br>**Escenario 2: Actividad completada**<br>**Given** una actividad pendiente ya fue registrada como realizada o resuelta<br>**When** el sistema evalúa los recordatorios asociados<br>**Then** no genera un nuevo recordatorio como si la actividad continuara pendiente. | EP04 |
| US26 | Generar un informe de emergencia en PDF | Como familiar autorizado, deseo generar un informe consolidado del adulto mayor para disponer de información organizada cuando sea necesario acudir a una clínica u hospital. | **Escenario 1: Generación de informe**<br>**Given** un familiar autorizado solicita el informe de un adulto mayor asociado<br>**When** el sistema consolida la información disponible<br>**Then** genera un documento PDF con el historial y los registros relevantes del adulto mayor.<br><br>**Escenario 2: Correspondencia del paciente**<br>**Given** un usuario autorizado gestiona o consulta a más de un adulto mayor<br>**When** solicita un informe de emergencia para uno de ellos<br>**Then** el documento contiene únicamente la información correspondiente al adulto mayor seleccionado. | EP04 |
| US27 | Proveer servicios REST para seguimiento familiar y emergencias | Como Developer, deseo disponer de servicios RESTful para consultas familiares, notificaciones e informes de emergencia para integrar estos procesos con la aplicación web. | **Escenario 1: Consulta autorizada**<br>**Given** un cliente autenticado con rol de familiar envía una solicitud válida sobre un adulto mayor asociado<br>**When** el servicio procesa la solicitud<br>**Then** la API devuelve únicamente la información permitida en modalidad de consulta.<br><br>**Escenario 2: Solicitud de recurso no autorizado**<br>**Given** un cliente intenta consultar información de un adulto mayor sin una relación autorizada<br>**When** el servicio procesa la solicitud<br>**Then** la API rechaza el acceso y no devuelve información sensible del seguimiento. | EP04 |
| US28 | Seleccionar un plan de suscripción | Como cuidadora o enfermera, deseo seleccionar el plan de Vitalita que se ajuste a mi forma de trabajo para acceder a las capacidades correspondientes a mi nivel de uso. | **Escenario 1: Selección de plan disponible**<br>**Given** una cuidadora dispone de una cuenta y consulta los planes vigentes<br>**When** selecciona un plan disponible<br>**Then** el sistema registra la selección y aplica las condiciones correspondientes una vez cumplidos los requisitos de activación.<br><br>**Escenario 2: Respeto de límites del plan**<br>**Given** una cuidadora utiliza un plan con límites definidos, como la cantidad de adultos mayores gestionables<br>**When** intenta realizar una operación que excede esos límites<br>**Then** el sistema mantiene las restricciones correspondientes al plan actual. | EP05 |
| US29 | Realizar el pago de una suscripción | Como cuidadora o enfermera, deseo pagar mi suscripción utilizando un medio disponible para activar o mantener el plan contratado. | **Escenario 1: Pago confirmado**<br>**Given** una cuidadora selecciona un plan de pago y un medio de pago habilitado<br>**When** la transacción es confirmada satisfactoriamente por el servicio de pago correspondiente<br>**Then** el sistema registra el pago y activa o mantiene la suscripción según el plan contratado.<br><br>**Escenario 2: Pago no confirmado**<br>**Given** una cuidadora inicia una transacción de suscripción<br>**When** el pago es rechazado, cancelado o no puede ser confirmado<br>**Then** el sistema no activa una suscripción de pago como si la transacción hubiera sido exitosa. | EP05 |
| US30 | Proveer servicios REST para suscripciones y pagos | Como Developer, deseo disponer de servicios RESTful para consultar planes, registrar suscripciones y procesar el estado de los pagos para integrar el modelo de monetización con la aplicación web. | **Escenario 1: Request válido de suscripción**<br>**Given** un cliente autorizado envía una solicitud válida para consultar o registrar una suscripción<br>**When** el servicio procesa la solicitud<br>**Then** la API devuelve el estado correspondiente del plan o suscripción sin exponer datos sensibles de pago.<br><br>**Escenario 2: Actualización de estado de pago**<br>**Given** el sistema recibe una confirmación válida del servicio de pago configurado<br>**When** procesa el resultado de la transacción<br>**Then** la API actualiza el estado de la suscripción de acuerdo con la confirmación recibida. | EP05 |
